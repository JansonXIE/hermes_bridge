01 / SYSTEM OVERVIEW

桥接服务是执行控制中心

默认采用异步 CLI 进程，而不是为每个 Claude Code 部署独立 HTTP 服务。任务结束后进程退出，任务记录与会话关联继续保留。

Hermes Agent任务拆解 · 提交 / 查询 / 取消 · 异常决策 · 结果汇总
↓ 提交任务 / 查询状态　↑ 进度摘要 / 完成事件
异步任务桥接服务API 与鉴权 → 持久化任务队列 → 并发调度 → 事件存储 → 通知投递
↓ 启动隔离进程　↑ 解析结构化输出
Claude Code A修复接口 · worktree-A
Claude Code B编写测试 · worktree-B
Claude Code C维护文档 · worktree-C
职责边界：Hermes 不必持续占用一次模型调用等待结果。后台服务维护进程和任务状态，在关键事件发生后通过适配器唤起 Hermes。
02 / TASK LIFECYCLE

从提交到自动回传

提交并立即返回任务编号

Hermes 调用任务工具；服务验证项目权限和请求幂等键，将任务落库后返回 task_id，任务先进入 queued。

领取任务并启动进程

Worker 原子领取任务、设置租约，准备独立工作目录，使用参数数组启动 Claude Code，并记录执行尝试编号。

持续采集执行事件

分别消费 stdout / stderr，按行解析结构化输出。记录事件序号、最近动作和日志；阶段更新节流汇总，详细日志保留在桥接服务。

持久化最终结果

结合最终结果事件、错误信息及退出码判定执行状态。保存摘要、变更引用、测试结论和产物位置；CLI 成功不等于业务验收通过。

可靠通知并唤起 Hermes

在同一数据库事务中保存终态和通知 Outbox。投递器重试发送，接收适配器持久化并去重后确认，通过 Hermes 支持的消息或调度入口触发后续处理。

建议状态模型

queued→starting→running→succeeded / failed

取消：queued → cancelled；starting / running → cancelling → cancelled。超时：执行状态 → timed_out。进程归属无法确认时进入 recovering，核对完成前不直接重跑。

仅在能够可靠检测并具备交互恢复能力时增加 input_required；不要假设非交互 CLI 能在任意权限提示处暂停并自动恢复。
03 / MULTI-INSTANCE CONTROL

可以并行，但必须有边界

并发与预算

初始可设 max_concurrency = 3，超过限制进入队列。按机器负载、模型配额与任务成本调整；该数值只是配置示例。

目录与资源隔离

同仓库使用独立 Git worktree 和分支。端口、数据库、缓存另行隔离；不可信任务使用容器或更强沙箱。

依赖与合并

任务支持 depends_on。依赖失败时阻止下游自动执行。合并由单独串行任务完成，处理冲突后重新运行测试。

监控信号代表什么处理方式
Worker 心跳 / 租约执行器是否可达、是否仍拥有任务租约失效后核对进程，不盲目重复执行
进程身份与存活Claude Code 进程是否存在结合进程启动时间或容器 ID，避免 PID 重用误判
last_event_at最近一次收到输出的时间长时间静默可告警，但不直接等同于卡死
阶段 / 工具执行摘要当前观察到的工作内容展示最近动作，不虚构百分比或内部思考
04 / API CONTRACT

最小可用接口

以下为自定义 HTTP 接口设计，不是标准 A2A 接口。所有接口都需鉴权，并校验任务所属用户与项目。

接口作用关键约定
POST /v1/tasks提交任务Idempotency-Key 请求头；202 返回 task_id
GET /v1/tasks批量监控按状态、会话、项目过滤；分页返回
GET /v1/tasks/{id}查询任务与结果状态、最近动作、验收信息、产物引用
GET /v1/tasks/{id}/eventsSSE 订阅进度事件持久化；Last-Event-ID 续传；过期游标需重新取快照
POST /v1/tasks/{id}/cancel请求取消幂等；确认停止进程树后再标记 cancelled

任务提交示例

{
  "project_id": "backend-api",
  "hermes_session_id": "hs_123",
  "prompt": "修复登录接口并运行相关测试",
  "timeout_seconds": 1800,
  "depends_on": []
}

完成通知示例

{
  "event_id": "evt_456",
  "type": "task.completed",
  "task_id": "task_789",
  "hermes_session_id": "hs_123",
  "status": "succeeded",
  "result_ref": "/v1/tasks/task_789"
}

示例中的标识符仅用于说明。project_id 映射服务端允许访问的项目；会话标识需验证归属。result_ref 由适配器通过可信基地址鉴权读取，不接受任意外部结果 URL。

Claude Code 执行方式
claude -p "执行分配的任务并报告变更与测试结果" \
  --output-format stream-json \
  --verbose \
  --include-partial-messages

以已安装版本的 claude --help 为准。生产代码使用进程 API 的参数数组与 cwd，不拼接 shell 字符串；长提示词按该版本支持的输入方式传入。提前验证认证、权限策略、输出事件格式和最终结果语义。

建议持久化的数据

tasks：任务 ID、用户与会话归属、项目、状态、幂等键、超时、依赖、工作目录、Claude 会话标识、结果引用。

attempts：执行尝试、Worker、租约、进程或容器身份、退出信息。events：事件 ID、任务内递增序号、类型、脱敏载荷。outbox：通知、重试时间、投递状态。

Hermes 会话、Claude 会话、任务 ID 与进程 ID 分开管理。续接采用 Claude Code 当前版本支持的机制，避免多个进程并发写入同一会话。

05 / DELIVERY & SECURITY

自动同步不只是一条 Webhook

至少一次投递 + 幂等消费

  • 结果与 Outbox 同事务提交，避免完成后漏通知。
  • 指数退避重试；超限进入待人工处理队列。
  • Hermes 接收适配器使用 event_id 去重。
  • 先可靠入队再应答；会话执行由独立消费者处理。

同一会话串行处理

  • 多个任务同时完成时，通过会话队列串行唤起。
  • 正在运行的 Hermes 回合不直接被修改历史。
  • 按任务关联结果，可短窗口合并通知。
  • 业务副作用也需幂等，不宣称端到端恰好一次。

进程与故障恢复

  • 原子领取任务，租约配合执行尝试编号防止旧 Worker 写回。
  • 取消先温和停止进程组，超时后强制终止。
  • 重启后核对执行器、进程身份和已保存事件。
  • 未知任务先恢复核对；带副作用任务不默认重跑。

权限与数据保护

  • 低权限账户、目录白名单、受限凭据与网络访问。
  • 不默认启用绕过权限确认的参数。
  • 回调地址由服务端配置，防止 SSRF；签名与防重放。
  • 日志脱敏；代码、输出和产物作为不可信输入处理。
06 / IMPLEMENTATION ROADMAP

先跑通闭环，再扩展协议

PHASE 1

单机最小实现

Python API 服务 + 独立 Worker + SQLite WAL + 本地持久化产物。数据库承担任务队列，原子领取且避免长事务；不依赖 API 请求内的临时后台任务。

PHASE 2

接入 Hermes

注册 start / get / list / cancel 工具；实现完成事件接收与会话队列。按实际 Hermes 版本接入扩展机制，不假设存在通用唤醒接口。

PHASE 3

多机与标准 A2A

扩展为 PostgreSQL + 队列 + 多 Worker + 对象存储。需要互操作时，再按选定 A2A 版本实现 Agent Card、任务、事件流、Artifacts 与可用的通知能力。

首版验收标准：同时提交 5 个任务且最多运行 3 个；任务目录隔离；可查询进度并断线续传；取消能停止子进程；回调失败后可重试且不重复唤起；服务重启后不丢已提交任务、不盲目重复执行；最终代码集成后重新测试。

Claude Code 什么时候退出

情况结果
正常完成claude -p 自己退出，状态为 succeeded 或 failed
预算用完Claude 自己停下，error_max_budget_usd
超时worker 发 SIGTERM，10 秒后仍未退出就 SIGKILL，状态为 timed_out
取消先 SIGTERM，再 SIGKILL，确认进程树全部停止后才标记为 cancelled

Claude 启动的子进程带有任务标记，或者处在同一进程组里，任务结束、超时或取消时都会一并清理。例外：用 setsid 加清空环境变量、systemd-run、docker run -d 等方式脱离进程树的程序，需要手动清理。可以用 ps -eo pid,etime,args | grep '[c]laude -p' 查看正在运行的 Claude，--name 参数就是 task_id。

10 / NEW SERVER

在新服务器上部署

准备环境

Linux 加 systemd，以实际使用者的账户操作。需要 Python 3.11 或更高版本、git，以及已登录的 claude（运行 claude -p "hi" 不报认证错误）。Hermes Agent 要装在同一台机器上，因为插件通过 127.0.0.1 访问 bridge。如果需要 git fetch，还要配好 gerrit 的 SSH 密钥。

拷贝代码

一键部署服务

cd ~/opt/a2a && deploy/setup.sh --restart-gateway

脚本依次完成：检查依赖；生成 ~/hermes-bridge/（含 bridge.toml、权限 600 的 bridge.env、data/）；安装并启动 systemd 服务，开启 linger，等健康检查通过；安装 Hermes 插件，写入 4 个变量，打开 allow_gateway_injection；重启网关。脚本可以重复运行，不会重新生成密钥，也不会覆盖手改过的配置。常用选项：--home 指定目录，--service 指定服务名，--api-port 和 --adapter-port 指定端口，--repo 和 --full-access 顺便添加项目。

手动添加项目

编辑 ~/hermes-bridge/bridge.toml，文件末尾有带注释的示例。每个 git 仓库写一个 [projects."ID"] 块，ID 中有 . 时必须加引号。repo 工作区要为每个子仓库各写一个块，工作区本身可以另配一个只读的 inplace 块。改完运行 check，再重启 @api 和 @worker。子仓库很多时，可以先用 add-projects <路径> --dry-run 预览会生成哪些 ID。

验证并告诉 Hermes 项目 ID

在微信里发一个只读的小任务。先收到 task_id，一两分钟后同一会话自动收到汇报，就说明链路正常。然后让 Hermes 把项目 ID 规则记进 memory。

风险与待办

当前风险

  • 没有沙箱：worktree 项目以 bypassPermissions 运行，和使用者是同一个账户，可以读到 ~/.hermes/.env（含微信 token）、bridge.env 和 SSH 密钥。禁止读取这些文件的规则对 shell 命令不起作用。
  • 可以 push 到 gerrit：只靠提示词约束，没有强制限制。
  • 微信入口是公开的：WEIXIN_DM_POLICY 和 WEIXIN_GROUP_POLICY 都是 open，白名单为空。能给 bot 发消息的人，都能间接在这台机器上执行命令。
  • 花费：最小一次调用约 0.2–0.5 美元，大型 review 很容易超过 5 美元。

建议待办

  • 把 WEIXIN_ALLOWED_USERS 设成只有本人，然后重启网关。

  • 定期运行 gc --days 14 回收旧的 worktree，任务记录和分支会保留。
